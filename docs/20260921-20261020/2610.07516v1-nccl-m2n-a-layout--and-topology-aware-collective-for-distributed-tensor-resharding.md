## 摘要
分布式训练与 rollout 生成通常使用不同的张量布局，因此需要跨不同进程组对模型权重进行重分片。这种 M 到 N 的重分布无法由标准集合通信直接表达。扁平直接发送会在目标副本间产生重复流量，而先聚集再广播会将网络注入集中到一个根节点，并传输目标端并不需要的数据。对于 256 个 GPU 上的 DeepSeek-V3，传统 all-gather 加 broadcast 占所报告的强化学习步骤时间的 29.4%。我们提出 NCCL M2N，一种面向分布式张量重分片的布局与拓扑感知集合通信原语。给定源与目标 mesh 及 placement，它推导所需的传输区域和全局通信调度。其分层路由在符合条件的目标 rank 之间平衡源端贡献，在目标 NVLink 域之间只转发一份副本，并通过 NVLink 完成本地复制。网络传输与本地复制重叠，避免源出口流量随副本数倍增。一个聚合数据移动模型刻画了两个阶段的限制。我们在配备 NDR InfiniBand 的 NVL72 集群中，最多 256 个 GB200 GPU 上评估 NCCL M2N。单次 FFN-MoE 层传输相比扁平直接发送最高实现 7.9 倍加速（9.8 ms 对 77.3 ms）。在另一项 256 GPU 的 DeepSeek-V3 NeMo-RL 实验中，NCCL M2N 将报告的权重同步时间从 5.78 s 降至 2.77 s，相比传统 all-gather 加 broadcast 实现 2.09 倍加速，并将步骤时间减少 12.7%。

## Abstract
Distributed training and rollout generation often use different tensor layouts, requiring model weights to be resharded across distinct process groups. This M-to-N redistribution is not directly expressed by standard collectives. Flat direct sends duplicate traffic across destination replicas, while gather-then-broadcast concentrates network injection at one root and transfers data that destinations do not need. For DeepSeek-V3 on 256 GPUs, legacy all-gather plus broadcast accounts for 29.4% of the reported reinforcement-learning step time. We present NCCL M2N, a layout- and topology-aware collective primitive for distributed tensor resharding. Given source and destination meshes and placements, it derives the required transfer regions and a global communication schedule. Its hierarchical route balances source contributions across eligible destination ranks, forwards one copy between destination NVLink domains, and completes local replication over NVLink. Network transfer and local replication overlap, avoiding replica-multiplied source egress. An aggregate data-movement model captures the limits of both stages. We evaluate NCCL M2N on up to 256 GB200 GPUs in an NVL72 cluster with NDR InfiniBand. A single FFN-MoE layer transfer achieves up to 7.9x speedup over flat direct sends (9.8 ms versus 77.3 ms). In a separate 256-GPU DeepSeek-V3 NeMo-RL experiment, NCCL M2N reduces reported weight-sync time from 5.78 s to 2.77 s, a 2.09x speedup over legacy all-gather plus broadcast, and reduces step time by 12.7%.

# NCCL M2N 论文结构化总结

## 1. 核心问题与研究背景

- **问题场景**：分布式深度学习中，张量按并行策略（DP/TP/PP/EP）被切分或复制到进程网格上，形成特定“布局（layout）”。在 RLVR 类强化学习训练中，策略训练（trainer）与 rollout 生成（generator）通常采用不同的并行配置，因此每次训练更新后必须把权重从一种布局重排为另一种布局——即 **M-to-N 布局重分布（resharding）**：M 个源 rank 以布局 A 持有全局张量，N 个目的 rank 需要布局 B。
- **为何重要**：该“weight refit”阶段位于 RL 迭代关键路径上，generator 必须等新权重到达才能开始下一轮 rollout。作者实测 DeepSeek-V3 在 256 GPU 上，传统 all-gather + broadcast 的权重同步占所报告 RL step 时间的 **29.4%**。
- **现有方案缺陷**：
  - **扁平直发（flat direct sends）**：每个源贡献被分别发往目的端的每一个副本，造成副本数倍的重复网络流量。
  - **gather-then-broadcast**：先把分片聚集到单一 root 再广播，避免源端重复，但流量集中在一个注入点，且向目的端传输其并不需要的完整张量。
  - 标准 NCCL 集合通信（ALL GATHER、ALL TO ALL、REDUCE SCATTER 等）固定参与者与逻辑模式，**无法接受两个任意布局并推导字节级重叠区域**；GIN/LSA 等底层机制只负责“搬运”，不负责“决定搬什么、在哪里复制”。
- **整体含义**：论文主张缺失的不是又一个 send 操作，而是一个**从两端布局描述自动推导全局调度、并联合考虑互连拓扑的一等集合通信原语**。

## 2. 方法论

### 2.1 核心思想
- 将“搬哪些字节”与“怎么搬”分离：由端点布局推导确定性传输调度（schedule），再由分层路由（hierarchical route）在拓扑上实现。
- 关键设计目标：(1) 只传输目的布局实际需要的字节；(2) 源贡献在合格的目的 leader 间负载均衡；(3) 副本 fan-out 留在 NVLink 域内，域间只转发一份。

### 2.2 布局模型与重分片语义
- 布局定义为三元组 **L = (S, M, p)**：S 为全局张量形状，M 为进程网格，p 为 placement 列表（`SHARD(d)` 或 `REPLICATE`）。
- 二维网格坐标到 rank 的映射：`rank(i0, i1) = r0 + i0·D1 + i1`（行主序连续区间，r0 为基 rank）。
- 每个 rank 的局部 shard 沿维度 d 的区间为 `[l_d, u_d)`，其中 `l_d = i_k·S_d/D_k`（当 p_k = SHARD(d)），`u_d` 用 `i_k+1` 代入；REPLICATE 维度取 `[0, S_d)`。实现要求 shard 维度可整除。
- Reshard 定义为：完成后每个目的 rank 持有 L_d 规定的局部 shard；**所有 rank 都提供两端布局描述**，从而各自独立推导出相同调度，调用者无需手写逐对通信表。
- 当前实现要求源网格与目的网格在 communicator 内是**不相交的 rank 区间**。

### 2.3 两个示例
- **示例 A（同维度 TP 重分片 + 目的端复制）**：S=[4,8]，源 `[1×4]`（TP=4, DP=1）→ 目的 `[2×2]`（TP=2, DP=2）。目的 TP slot 各合并两个相邻源 shard（G4←T0+T1，G5←T2+T3），G6/G7 分别是 G4/G5 的 DP 副本。扁平直发会把唯一负载传两份。
- **示例 B（PP>1 的逐 stage 分解）**：TP=2、PP=2 的 trainer → TP=1、PP=1 的 generator。不构造跨全部 trainer 的 communicator，而是**每个 PP stage 发起一次 reshard**，各自使用独立 PP communicator（{0,1,4} 与 {2,3,4}），rank 4 作为共同目的在两次调用中分别累积一个 stage 的完整张量。reshard 原语本身无需改动。

### 2.4 确定性调度推导
- 对源 s 与目的 t，逐维计算重叠区间 `I_δ(s,t) = [max(l_sδ, l_tδ), min(u_sδ, u_tδ))`。
- 若所有维度区间非空，则组合区间即精确贡献；否则跳过该对。
- 复制的源副本折叠到**一个确定性 owner**，保证所有 rank 枚举结果一致、无需额外协调。

### 2.5 分层拓扑路由
- 设 K 个目的 shard，第 j 个 shard 有 q_j 个唯一源贡献，每域 ρ 个本地副本。按源 shard 排序后，每个副本基础负载 `a_j = ⌊q_j/ρ⌋`，前 `b_j = q_j mod ρ` 个副本各多承担 1 个，**负载差最多为 1**。
- 非零负载的副本成为 leader：每个贡献经一个 leader 注入，跨域环形转发，再在域内通过 NVLink 复制给其余 ρ−1 个副本。

### 2.6 聚合数据移动模型（下界，不含打包/协议/启动开销）
- 记号：B 为唯一全局负载，N_s 为活跃源 GPU 数，K 为目的 shard 数，r_d 为副本数，d 为 NVLink 域数，ρ = r_d/d，β_N、β_V 分别为网络与 NVLink 单向带宽。
- **分层路由**：`B_N = min(N_s·β_N, K·ρ·β_N)`，`T_network = B/B_N`；`T_NVLink = (ρ−1)B/(K·ρ·β_V)`；`T_SOL = max(T_network, T_NVLink)`。多域时域间环形只传一份，稳态不随 d 倍增。
- **扁平直发**：`B_flat_N = min(N_s·β_N, K·r_d·β_N)`，`T_flat = r_d·B/B_flat_N`；当源注入为瓶颈时 `T_flat/T_SOL ≈ r_d`。
- **AG+bcast**：`T_SOL_AG+Bcast ≈ max(T_SOL_AG, T_SOL_Bcast)`；源受限时 `T_SOL_Bcast ≈ N_s · T_SOL_M2N`，即 M2N 可利用 N_s 条并发注入路径。

### 2.7 实现
- 初版 v0.2 支持 1–2 维进程网格、1–3 维张量、每个布局至多一个 sharded mesh 轴。
- 两种传输：**PACK**（将 strided 贡献收集到连续 staging buffer，再分层传输并 scatter 回目的 buffer）与 **PIPE**（beta，按有界 chunk 流水线，device-side 或 host-driven RMA 推进）；均保持 caller-stream 顺序。
- 以 `nccl_m2n` 组件开源在 NVIDIA NCCL Extensions 仓库，提供 C 与 Python 接口。
