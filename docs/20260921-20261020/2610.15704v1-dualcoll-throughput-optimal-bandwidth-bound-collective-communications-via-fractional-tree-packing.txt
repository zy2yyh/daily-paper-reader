# Abstract 

Large-scale distributed training increasingly makes collective com-munication bandwidth-bound. In modern GPU clusters, commu-nication libraries such as NCCL implement collectives including AllReduce over heterogeneous interconnects such as NVLink, In-finiBand, and Ethernet, making efficient use of available network bandwidth a central systems challenge. ForestColl showed that collective communication on such fab-rics can be formulated using fractional tree packing; its scalable polynomial-time construction is developed for AllGather, with AllReduce obtained by composing AllGather and ReduceScatter. We present DualColl, which targets bandwidth-bound AllReduce directly. Under the tree-based AllReduce model, DualColl applies a Garg–Könemann-style multiplicative-weights algorithm and, for any 0 < 𝜖 < 1, computes a feasible schedule whose throughput is at least (1 − 𝜖 )2 of the optimal AllReduce throughput. Its key compo-nent is an exact minimum-cost collective-tree oracle that projects physical-link dual prices onto a logical graph of participating ranks, reducing each iteration to shortest-path computations followed by a minimum spanning tree. We further extend the framework to local equal-next-hop packet-sprayed routing and to networks without explicit per-tree bandwidth control. For the latter, we introduce a tree-coupled max-min bandwidth-sharing model and show that tree duplication approximates an explicit fractional allocation with a provable accuracy-complexity tradeoff. Finally, we extend the fractional-packing framework to additional collective operations and multiple concurrent collective groups.

# 1 Introduction 

Large-scale distributed training relies heavily on collective commu-nication. In data-parallel training, for example, workers compute gradients locally and then use AllReduce to obtain the same ag-gregated result. Similar communication patterns arise in tensor, pipeline, and expert parallelism, as well as distributed inference. As model sizes, accelerator counts, and local computation rates grow, these collectives increasingly become bandwidth-bound, making efficient use of network capacity a central performance concern. In GPU clusters, collective operations are commonly imple-mented by communication libraries such as NVIDIA NCCL, which provides topology-aware implementations of AllReduce, AllGather, ReduceScatter, and related operations across multi-GPU and multi-node systems [6]. Such systems combine heterogeneous resources: intra-node links such as NVLink or NVSwitch may be substantially faster than inter-node Ethernet or InfiniBand links, and oversub-scription may vary across the network hierarchy. Consequently, ob-taining high collective throughput requires communication sched-ules that account for the capacities and topology of the underlying fabric. A useful abstraction for bandwidth-bound collective commu-nication is a collection of communication trees. For AllReduce, a tree reduces a data chunk toward a root and broadcasts the result back along the tree. Different chunks may be assigned to different trees, each operating at a continuous rate. With data partitioned proportionally to these rates, the resulting steady-state collective throughput is the sum of the bandwidths assigned to the active trees. ForestColl [16] established fractional tree packing as a powerful approach to collective scheduling on heterogeneous fabrics. In this formulation, candidate trees receive continuous rates whose sum is maximized subject to physical-link capacity constraints. ForestColl’s scalable polynomial-time construction is developed for AllGather, with AllReduce obtained by composing AllGather with ReduceScatter. This composition, however, is not guaranteed to be optimal for AllReduce, as the counterexample in Appendix A shows. DualColl instead targets bandwidth-bound AllReduce directly. It retains the fractional tree-packing abstraction but develops a differ-ent algorithmic framework for solving it. For the tree-based AllRe-duce formulation, DualColl computes a feasible solution whose throughput is within a (1 − 𝜖 )2 factor of the optimum. To the best of our knowledge, DualColl is the first polynomial-time algorithm with a provable near-optimality guarantee for bandwidth-bound AllReduce on switched topologies. DualColl uses a Garg–Könemann-style multiplicative-weights algorithm. The algorithm maintains a dynamic price for every phys-ical link and repeatedly requests a minimum-cost collective tree. Its key problem-specific component is an exact oracle that projects physical-link prices onto a logical graph containing only the partic-ipating ranks and then computes a minimum spanning tree. This avoids enumerating the exponentially many candidate trees. We also extend the framework toward practical network op-eration. First, we consider local equal-next-hop packet spraying, in which a logical flow is distributed fractionally over multiple shortest-path links rather than routed along a scheduler-selected path. Fine-grained multipath packet spraying is increasingly rele-vant in AI-oriented network fabrics; for example, the Ultra Ethernet Transport architecture supports packet spraying across multiple

Second, because real networks do not generally expose explicit per-tree bandwidth control, we introduce a tree-coupled max-min bandwidth-sharing model. We show that duplicating trees acts as an effective weight under max-min sharing and can approximate a desired fractional allocation with a provable accuracy–complexity tradeoff. # 2 Model and ForestColl Foundation 

This section introduces the network and collective-communication model used by DualColl. We then restate the fractional tree-packing formulation underlying ForestColl, which serves as the starting point for our work. Throughout this section, we consider the base-line scheduler-routed model in which every logical communication edge is mapped to a single chosen physical path. The extensions considered later are introduced separately in Section 5.

# 2.2 Tree-Based AllReduce 

In an AllReduce operation, every participating rank initially holds an input array, and every rank must obtain the element-wise reduc-tion of all input arrays. A tree-based AllReduce schedule performs this operation in two phases. First, data is reduced from the leaves of a rooted logical tree toward its root. Intermediate ranks combine the values re-ceived from their children with their own local values. Second, the root broadcasts the reduced result back to all ranks along the tree. Note that because data is combined at each intermediate node, the amount of data that a node sends does not increase as we go higher in the tree. A logical tree contains only participating compute nodes. Switches are not represented as logical vertices; they appear only in the physical network over which the logical edges are routed. Let 𝑇 be a logical spanning tree over 𝑅 . Each logical edge of 

𝑇 is mapped by the scheduler to a single physical path in 𝐺 . The complete routing of the logical edges determines how much capacity the tree consumes on every physical edge. A schedule may use several logical trees in parallel. The input array is divided into disjoint chunks, and each chunk is assigned to one tree. Let 

T = {𝑇 1,𝑇 2, . . . ,𝑇 𝑘 }

be the set of selected trees, and let 𝜆 𝑇 ≥ 0 denote the bandwidth assigned to tree 𝑇 , per direction, so that the reduce and broadcast phases each operate simultaneously at rate 𝜆 𝑇 .Restricting attention to schedules of this tree form loses no throughput. Intuitively, consider a tiny shard of the data which is never split by some optimal schedule. If two ranks both act as roots for that shard—each independently computing the fully re-duced value—then work is wasted: the two roots must communicate their own contributions to one another in any case, so rather than exchanging raw contributions it is always at least as good for one of them to send the other its fully reduced result, eliminating one of the two roots. Iterating this observation collapses every shard to a single root, after which its reduction and broadcast each form a tree; a further exchange argument shows the reduce and broadcast trees may be taken identical. We state the resulting guarantee here and prove it in Section 3.

# 3 Optimality of Tree-Based AllReduce 

This section proves Theorem 2.1. The model of Section 2 restricts AllReduce schedules to collections of logical trees, each of which reduces a shard of the data toward its root and then broadcasts the reduced shard back along the same tree. We show that this restriction loses no throughput, so the optimum OPT of the frac-tional tree-packing formulation is the bandwidth-optimal AllRe-duce throughput itself, and not merely the optimum over a restricted class of schedules. Starting from an arbitrary bandwidth-optimal schedule, we normalize it in three steps, none of which increases any per-edge load or the completion time: each shard is first re-duced to a single root (Lemma 3.4), its reduce and broadcast phases are then made trees rooted there (Lemma 3.5), and finally, under single-path routing, the two trees are made to coincide (Lemma 3.6). Lemmas 3.1–3.3 are the tools used along the way. 

Setting. We fix a shard : a unit of data that the schedule treats uniformly, so that the shard is never split into smaller pieces and every rank’s contribution to it is moved and reduced as a single whole. A schedule for the shard is a finite set of flows , each carrying a payload from one rank to another, and each assigned a rate, that is, a bandwidth. The payload of every flow is the reduction of the contributions of some subset of the ranks, and the fully reduced shard is the reduction over all ranks; since reduction is applied elementwise, every payload has the same size as the shard. A flow of rate 𝑏 places a load of 𝑏 times the fraction of its traffic routed over directed edge 𝑒 on 𝑒 ; the load on 𝑒 is the sum of these over all flows of all shards, and the schedule is feasible if the load on every directed edge 𝑒 is at most 𝐶 𝑒 . As in Section 2, every physical link has equal capacity in both directions, 𝐶 𝑒 = 𝐶 ¯𝑒 , where ¯ 𝑒 denotes the reverse of directed edge 𝑒 .Flow 𝑔 depends on flow 𝑓 if the payload of 𝑔 is computed from data delivered by 𝑓 ; the dependency relation is acyclic. In the bandwidth-bound model, a flow 𝑔 that depends on 𝑓 does not wait for 𝑓 to end: it starts as soon as the data of 𝑓 begins to arrive and pipes that data onward as it moves, so dependent flows run con-currently. We call a rank a root for the shard if it obtains the fully reduced shard without receiving it, that is, it computes the final value locally from partial values it has received. At least one root exists, since the first rank to hold the fully reduced shard cannot have received it, and every rank ends holding the fully reduced shard. For a single directed phase 𝑇 (a reduce in-tree or a broadcast out-tree, together with its physical routing) we write 𝑎 𝑒 (𝑇 ) for the load 𝑇 places on directed edge 𝑒 per unit rate. Lemma 3.1 (Promotion to the fully reduced shard). Let 𝑓 

be a flow whose source already possesses the fully reduced shard. If the payload of 𝑓 is replaced by the fully reduced shard, and the same replacement is applied to every flow that depends on 𝑓 , directly or transitively, then the resulting schedule is still legal. 

Proof. Consider the set D consisting of 𝑓 together with all flows that depend on 𝑓 directly or transitively. We promote every flow in D to carry the fully reduced shard. We must check that each promoted flow’s payload is actually available at its source when the flow is sent, so that the schedule remains executable. Process the flows of D in an order consistent with the depen-dency relation, which is possible since that relation is acyclic. The first flow is 𝑓 itself, and its source possesses the fully reduced shard by hypothesis, so it can send it. Consider any later flow 𝑔 ∈ D with source 𝑢 . Every flow of D on which 𝑔 depends has been processed earlier and now delivers the fully reduced shard, so 𝑢 is receiv-ing the fully reduced shard from flows that 𝑔 depends on and can therefore send it. Thus every promoted flow is executable. A rank that receives a promoted flow receives the fully reduced shard, and holding the final value it is complete for this shard regardless of any other partial values, so its state is consistent. A flow not in D does not depend on 𝑓 , so none of its inputs were altered and its payload is unchanged; hence every rank outside the recipients of D ends exactly as before, and in particular every rank that was already complete remains complete. The schedule is therefore legal. □

# 4 DualColl’s Algorithm 

Section 2 formulated bandwidth-bound AllReduce scheduling as the fractional tree-packing problem in Equations (1)–(3). Although this formulation contains only one capacity constraint per physical link, it has one variable for every feasible collective tree and its physical-path mapping. The number of such routed trees is exponential in the number of participating ranks, which prevents their direct enumeration. DualColl solves this problem using a Garg–Könemann-style multiplicative-weights framework. Rather than constructing the complete linear program, the algorithm maintains a positive price for every physical edge and repeatedly selects a collective tree having minimum cost under the current prices. The selected tree is added to the fractional packing, after which the prices of the physical edges it uses are increased. The key problem-specific component of the framework is there-fore a minimum-cost collective-tree oracle. DualColl implements this oracle by projecting the current physical-edge prices onto a log-ical graph over the participating ranks and computing a minimum spanning tree in the projected graph.

# 5 Packet Spraying and Max-Min Fairness 

The fractional packing algorithm of Section 4 computes an explicit bandwidth allocation under the scheduler-routed model. Namely, it returns a set of logical trees 𝑇 1, . . . ,𝑇 𝑘 and assigns each tree a continuous bandwidth 𝑎 𝑖 , with each logical edge mapped to a single chosen physical path. In that model, the scheduler directly controls both the route of every flow and the bandwidth of every tree, subject to the physical capacity constraints. Real deployments differ from this idealization in two respects. First, when packet spraying is used, the fabric spreads a logical flow across several physical paths rather than allowing the scheduler to choose a path. Second, systems usually do not provide explicit per-tree bandwidth control; instead, bandwidth is allocated dynami-cally by the transport protocol and by the network, often according 

> 8DualColl: Throughput-Optimal Bandwidth-Bound Collective Communications via Fractional Tree Packing

to a max-min fairness principle. This section addresses both. We first describe the routing mechanics of the packet-spraying model, which are independent of how bandwidth is subsequently allocated. We then define the tree-coupled version of max-min fairness appro-priate for collective communication, generalize it to packet-sprayed flows, and finally show that by duplicating trees, the protocol model can approximate any explicit fractional allocation arbitrarily well. Packet spraying also forces a change in the formulation itself, which we flag at the outset. Under the scheduler-routed model we were entitled to assume that a tree reduces and broadcasts along the same logical tree: Lemma 3.6 shows that any schedule with distinct reduce and broadcast trees can be converted, at no loss of throughput, into one built from such simple trees. That argument reverses a tree’s routing and charges the reversed phase the mirrored load on the opposite directed edges, which is valid precisely because single-path routing sends a reversed logical edge back along the same physical path, flipping the induced loads 𝑝 𝑒 (𝐹 )

on every physical link. Local equal next-hop spraying does not have this property. What survives is the weaker structure of Lemmas 3.4 and 3.5, which make no reference to how a logical edge is routed— they use only the dependency structure among flows and the fact that the schedule does not split a shard—and therefore hold verbatim under packet spraying: each shard still has a single root, with a reduce in-tree and a broadcast out-tree rooted at it, but the two trees need not coincide. Accordingly, in the packet-sprayed setting a packing variable is a pair consisting of an in-tree and an out-tree sharing a root, and the oracle must select the best such pair rather than a single tree. Section 5.2 develops this formulation and its oracle. 

# 5.1 Packet-Spraying Routing 

We first describe packet spraying purely as a routing mechanism, independent of how bandwidth is later allocated. Modern datacen-ter networks often contain several shortest paths between a pair of endpoints. In packet spraying, traffic between a pair of endpoints is split across the shortest paths. Since collective communication transfers large data chunks, we represent the long-run traffic dis-tribution induced by packet spraying as fractional physical-link loads. We consider local equal next-hop packet spraying. At each switch, a packet is forwarded uniformly at random among all outgoing next hops that continue along a shortest path to its destination. The eligible next-hop set is determined by the routing topology and does not change in response to instantaneous congestion or Layer-2 PAUSE state. This forwarding rule induces fixed long-run physical-link fractions for each logical flow, which can therefore be incorporated directly into the fractional tree-packing model. We do not consider adaptive packet spraying in which congestion or flow-control state dynamically changes next-hop eligibility. # 5.4 Max-Min Fair Realization 

We now turn to how bandwidth is allocated once trees are in-stantiated. In the packet-sprayed formulation, we treat each re-duce/broadcast tree pair as one collective object whose constituent

flows share a common rate; all definitions below apply to such pairs by summing the loads of both phases. We first define tree-coupled max-min fairness for single-path routing, and then generalize it to packet-sprayed flows. In ordinary flow-level max-min fairness, each flow is treated independently. A collective tree is different: it is not a single physical flow, but a collection of physical flows corresponding to the logical edges of the tree. Moreover, the tree can only make progress at the rate of its slowest flow. If one edge of the tree is bottlenecked, the whole tree pipeline slows down to that rate. We therefore use a tree-coupled max-min fairness model. Each tree 𝑇 𝑖 consists of a set of physical flows induced by routing its logical edges over the physical topology. The bandwidth 𝐵 (𝑇 𝑖 ) of the tree is the common rate at which all of its flows operate. If any flow of 𝑇 𝑖 becomes bottlenecked, then all other flows of 𝑇 𝑖 are clamped to the same rate. This captures the synchronous nature of a tree-based collective: a tree cannot complete its assigned data chunk faster than its slowest required communication path. Assume first that every logical edge is routed over a unique phys-ical path. The tree-coupled max-min allocation can be described by the following iterative procedure. It is important to note that this procedure describes how the resulting allocation is calculated , not a computation that the net-work carries out. The bandwidth given to each tree is determined by the network itself, dynamically, according to its transport and congestion-control protocol. The network does not run this algo-rithm; rather, the algorithm is our model for predicting the rates that the network’s max-min fair sharing will produce, so that the scheduler can reason about them when choosing which trees to instantiate. Tree-coupled max-min fairness is thus an idealized an-alytical model of protocol-determined bandwidth allocation. We do not claim that any particular congestion-control protocol realizes exact max-min fairness; rather, max-min fairness is a standard and analytically tractable approximation of the rates that such protocols tend to produce, and we use it to reason about the effect of tree duplication.

# 5.5 Emulating Explicit Bandwidths 

We now show how to emulate an explicit bandwidth allocation using only max-min fair sharing. The key idea is tree duplication. If one tree should receive twice as much bandwidth as another, we instantiate two identical copies of the first tree and one copy of the second. Under max-min fairness, identical competing copies receive equal rates; the total bandwidth assigned to the original tree is the sum of the rates of its copies. For example, suppose the explicit allocation assigns bandwidth 100 to Tree A and bandwidth 50 to Tree B. If only these two trees are instantiated, a max-min fair protocol may not produce the desired ratio. Instead, we instantiate two copies of Tree A and one copy of Tree B. If the three instantiated trees receive equal bandwidth 50, then the two copies of Tree A together achieve bandwidth 50 + 50 = 100, while Tree B receives bandwidth 50.

Our Solution. By Lemma 6.1, applied with one class per root, this max-min objective again has the same optimum as a fractional packing over 𝑛 -tuples of trees. Solving ReduceScatter directly there-fore requires only one change to the AllGather oracle of Section 6.1. There, a packing variable is an 𝑛 -tuple of trees, one rooted at each node, and the oracle returns for each root a minimum-weight out -arborescence, whose edges are directed away from the root, match-ing the outward flow of a broadcast. Everything else is unchanged: the projected weights are computed from the current dual prices exactly as before, each tuple receives a common bandwidth, and the surrounding multiplicative-weights framework, its stopping rule and its scaling step are untouched. Because the two oracles differ only in the orientation of the arbores-cences they compute, and an in-arborescence on 𝑛 nodes costs the same as an out-arborescence, ReduceScatter inherits the AllGather running time and approximation guarantee, and the argument is valid under packet-sprayed routing as well as under single-path routing. 

# 6.3 Multiple Concurrent AllReduce-Sets 

In complex distributed systems, an AllReduce-set is a specific sub-set of compute nodes participating in an independent AllReduce operation. We consider two distinct optimization objectives for this scenario: maximizing the total aggregate bandwidth across all con-current sets, or maximizing the bottleneck (slowest) AllReduce-set. 

Our Solution. An important assumption required for optimality in this context is that compute nodes only participate in the routing and computation of their own AllReduce-sets. Therefore, a spanning tree for a given set contains only and all the nodes belonging to that specific set. To maximize the total aggregate bandwidth across all sets, we utilize the original fractional packing algorithm (Section 4). During each oracle iteration, the oracle computes the MST for each active AllReduce-set independently, and strictly returns the single tree (from any set) with the absolute minimum weight. Alternatively, to maximize the slowest AllReduce-set, we apply Lemma 6.1 with one class per concurrent set: the bottleneck objective then has the same optimum as a fractional packing whose columns are 𝑘 -tuples of trees, one spanning each AllReduce-set, all sharing a common rate. To solve this, we structure our oracle to compute independent spanning trees per set during each iteration (utilizing only the compute nodes relevant to that specific set). # 7 Related Work 

Collective communication libraries and algorithms. High-performance distributed systems have long relied on optimized collective-communication algorithms. Classical MPI work de-veloped bandwidth-efficient algorithms for operations such as AllReduce and ReduceScatter [7, 8, 13], while modern distributed-training systems commonly use GPU-oriented libraries such as NVIDIA NCCL [6] and frameworks such as Horovod [10]. Blue-Connect adapts AllReduce to heterogeneous network hierarchies by decomposing it into parallel ReduceScatter and AllGather oper-ations that can be mapped to different network fabrics [2]. More recent systems provide increasingly programmable communication layers; for example, MSCCLang provides a language for writing custom GPU collective algorithms together with an optimizing compiler [3], while MSCCL++ provides low-level communication primitives and a DSL for constructing high-performance GPU communication kernels [5]. DualColl is complementary to these systems: our focus is the algorithmic construction of provably high-throughput schedules for a given heterogeneous network fabric. 

Topology-aware synthesis and tree packing. Several systems auto-matically construct collective algorithms for a given topology. SCCL formulates collective synthesis as an SMT problem and searches for algorithms along the latency–bandwidth tradeoff [1], while TACCL uses user-provided communication sketches to guide synthesis on larger heterogeneous topologies [11]. Blink [15] is particularly re-lated to DualColl: it applies a multiplicative-weight approximation algorithm to pack spanning trees on heterogeneous GPU topologies and uses the resulting structures to implement collectives including AllReduce. DualColl differs in the optimization problem and guar-antees considered here: we formulate bandwidth-bound AllReduce directly, prove that the tree-based restriction loses no through-put under our full-duplex model, and obtain a polynomial-time 

(1 − 𝜖 )2 approximation guarantee for the resulting AllReduce prob-lem. Blink’s tree-packing formulation does not directly support switched topologies. 

ForestColl. The work most closely related to ours is Forest-Coll [16], which constructs throughput-optimal collective schedules on heterogeneous network fabrics by packing broadcast or aggregation spanning trees. Its optimality characterization is based on the network bottleneck cut and also enables switch nodes to be eliminated while preserving the relevant cut capacities. ForestColl’s polynomial construction is developed for AllGather and ReduceScatter, with AllReduce obtained by composing the two. We show that this composition can be strictly suboptimal for AllReduce (Appendix A) and instead optimize AllReduce directly. Our treatment of switches also differs: rather than eliminating them using a cut transformation, DualColl projects physical-link dual prices onto a logical graph over participating ranks; switch links remain fully represented through the projected edge costs and capacity constraints. Finally, whereas ForestColl considers scheduler-routed single-path routing and a single collective group, DualColl additionally addresses packet-sprayed routing, tree-coupled max-min bandwidth allocation, and multiple concurrent collective groups. 

# 8 Conclusion 

We formulated the scheduling of bandwidth-bound collective operations as a fractional tree-packing LP under an explicit bandwidth-allocation model. By combining the Garg–Könemann algorithm with an exact dual-cost projection oracle, we obtain a fully polynomial-time approximation scheme (FPTAS) that computes a solution arbitrarily close to the optimal fractional tree-packing value on any static datacenter topology satisfying our network model. To the best of our knowledge, DualColl is the first polynomial-time algorithm with a provable near-optimality guarantee for bandwidth-bound AllReduce on switched topologies. We further extend the framework beyond the scheduler-routed setting: to local equal next-hop packet spraying , where the reduce and broadcast trees must be packed as pairs; to networks without explicit per-tree bandwidth control, where tree duplication realizes a fractional allocation under tree-coupled max-min fairness; and to the other collective operations and to multiple concurrent collective groups.

# A Sub-Optimality of ReduceScatter+AllGather 

This appendix exhibits an instance on which an AllGather-optimal set of trees, composed into an AllReduce in the usual way, is strictly worse than the optimal AllReduce. It shows that optimality of the AllGather phase does not certify optimality of the composed AllRe-duce. 

The instance. Consider five ranks 0 , 1, 2, 3, 4 connected in a path, with links {0, 1}, {1, 2}, {2, 3}, {3, 4}, each of capacity 4 in each di-rection (Figure 3a). 

An optimal AllGather solution. For AllGather, rank 4 must receive the data of all four other ranks, and every such stream crosses the directed edge 3 → 4. If all trees are run at a common bandwidth 

𝛽 , this forces 4 𝛽 ≤ 4, so 𝛽 ≤ 1; a solution with 𝛽 = 1 is therefore AllGather-optimal. Consider the following set of broadcast trees, one rooted at each rank, all run at 𝛽 = 1:

𝑇 0 is the twist: instead of handing its data to rank 1 first, rank 0 sends a single logical flow to rank 2, routed over the physical path 0–1–2, and rank 2 then serves ranks 1 and 3 (Figure 3b). The link {1, 2} now carries 6 units of load per unit of bandwidth in both directions. The reason is that the directed edge 1 → 2 already carried 2 units in the AllGather phase: one from 𝑇 1, whose logical edge 1 → 2 uses it directly, and one from the twisted tree 𝑇 0, whose logical edge 0 → 2 is routed over the physical path 0–1–2 and therefore traverses 1 → 2 as well.
