## 摘要
集合通信是大规模分布式训练中的关键性能瓶颈。现有库和合成框架在假设拓扑静态且链路容量达到峰值的情况下，一次性计算开环调度。然而在生产环境中，持续性灰色故障可能悄无声息地使链路吞吐量和时延退化数小时，导致预计算调度在执行期间损失大部分效率。本文提出基于测量的集合通信库（MCCL），该集合通信库在运行时网络测量与动态调度合成之间形成闭环。MCCL 被动测量 GPU 到 GPU 吞吐量，检测持续性退化，利用热启动的合成器重新合成受影响的通信密集型调度，并在不中断训练的情况下对其进行热切换。我们在多节点硬件原型上验证完整闭环，并使用仿真评估集群规模场景。在实验中，MCCL 引入的开销可忽略不计（<2%），同时保持较高的测量精度（误差 <1.2%）和较低的调度热切换时间（约 12 ms）。值得注意的是，在灰色故障下，对于 Llama 和 DeepSeek 等最先进 LLM 的模拟训练负载，MCCL 相比静态调度最多可将训练时间缩短 4.99 倍。

## Abstract
Collective communication is a critical performance bottleneck in large-scale distributed training. Existing libraries and synthesis frameworks compute open-loop schedules once, assuming a static topology and peak link capacities. In production, however, persistent gray failures can silently degrade link throughput and latency for hours, causing pre-computed schedules to lose much of their efficiency during execution. In this paper, we present Measurement-based Collective Communication Library (MCCL), a collective communication library that closes the loop between runtime network measurement and dynamic schedule synthesis. MCCL passively measures GPU-to-GPU throughput, detects persistent degradation, re-synthesizes the affected communication-intensive schedules with warm-started synthesizers, and hot-swaps them without interrupting training. We validate the complete loop on a multi-node hardware prototype and use simulations to evaluate cluster-scale scenarios. In our experiments, MCCL incurs negligible overhead (<2%) while maintaining high measurement accuracy (<1.2% error) and low schedule hot-swap time (about 12 ms). Notably, under gray failures, MCCL reduces training time by up to 4.99x over static schedules on simulated training workloads for state-of-the-art LLMs such as Llama and DeepSeek.

## 2. 方法论

### 2.1 核心思想

- 从"**optimize-once**"转向"**always-optimizing**"：利用训练迭代的重复性，把每次 collective 变成免费的测量机会，形成"被动测量 → 漂移检测 → 选择性重合成 → 热切换"的闭环。
- **控制器–执行器架构**：
  - **Controller（慢路径）**：后台服务，处理遥测、诊断网络健康、执行调度合成；含 Schedule Manager 与 Schedule Optimizer。
  - **Executor（快路径）**：运行在 GPU 上，执行 collective、被动测量、热切换；含 Online Rescheduler 与 Measurement。
- **优化对象**：通信密集型 AllGather 与 AllToAll；AllReduce 通过标准分解处理——ReduceScatter 阶段保留静态调度以利用 SHARP 网内计算，AllGather 阶段交由 MCCL 动态优化。

### 2.2 动态优化循环

- **启动阶段**：输入应用 profile（collective 列表与频率）和初始 overlay 拓扑（通过探测获得容量），Schedule Manager 调用 Optimizer 生成基线调度下发给 Executor；也可跳过，直接回退到 NCCL ring。
- **运行时阶段**：Measurement 持续被动采样，经 RDMA 异步写入 Controller 的测量矩阵；Schedule Manager 用 **EWMA（平滑因子 α）** 过滤微突发，得到平滑吞吐 M_a；诊断后仅对受影响的 collective 触发重优化；新调度经 Online Rescheduler 热切换。

### 2.3 Schedule Manager：重优化选择算法（Algorithm 1）

- 输入：图 G(V,A)、测量 M、collective 集合 S 及其活跃调度、瓶颈割 {K_s}、基础松弛 {base_slack_{s,a}}、阈值 Γ。
- **Phase 1**：计算调度 s 的瓶颈速率 `x_min(s) = min_{a: n_a>0} M_a / n_a`，其中 n_a 为跨链路 a 的 chunk 数。
- **Phase 2**：仅遍历瓶颈割 K_s 中的链路，计算当前松弛 `(M_a − n_a·x_min(s))/M_a` 与基础松弛的偏差 δ_a，取最大值。
- **Phase 3**：若 `max δ_a > Γ`，调用 Schedule Optimizer 重合成。
- **抖动抑制**：Γ 与 α 联合调优；若退化在重合成期间消失则中止；因灰色故障持续时间远长于合成周期，实际抖动风险低。若故障落在非关键割上或整割等比缩放，则正确抑制重优化。

### 2.4 Schedule Optimizer

**AllToAll：基于列生成（CG）的 Dantzig–Wolfe 分解**

- 建模为吞吐最大化问题（式 1–4）：`max z`，约束 (2) 各 tensor 流量 ≥ z（max–min 目标），(3) 链路容量约束（β 为树内使用链路 a 的最短路径数），(4) 非负。
- 该式是紧凑弧基多商品流模型的 Dantzig–Wolfe 重写（附录 G 给出完整推导）。
- **RMP + pricing 交替**：pricing 子问题对每个 tensor 寻找最短路径树 T_c，使 `Σ β·α_a < α_c`（α_a 为拥塞价格，α_c 为吞吐边际价值）。
- **时间扩展图 G̃**：节点复制 m_s 份，交换机链路为瞬时边、其余为前向步进边；DAG 按拓扑序求解，复杂度 `O(|Ṽ|+|Ã|)`，天然偏好浅树。在线场景固定 `m_s=|V|−1`；附录 D 给出二分搜索最小步数的可选方案。
- **舍入**：CG 收敛后采用 deep-dive rounding 提取 ≤10 chunk 的可执行调度，实测与 MILP 最优的最大差距 **2.13%**（附录 F）。

**AllGather：ForestColl-warm**

- 保留 ForestColl 三阶段：①最大流计算最大吞吐；②交换机移除（抽象为逻辑链路）；③BFS 树生成。
- **核心增强**：用**类 A\* 的历史引导 BFS**，依据上一次最优 arborescence 重排候选链路顺序，利用"灰色故障只影响少量链路"的局部性大幅剪枝，实现热启动。
- **附录 C 可选延迟优化**：用凸分段线性惩罚（斜率随负载递增）+ min-cut 约束 + 割平面法改进交换机移除，降低最大树深以减小延迟，与吞吐目标按字典序（big-M）组合。

### 2.5 Executor

**Online Rescheduler（热切换）**

- 基于 MSCCL 动态加载算法，改编 MCCS 机制：后台线程异步加载新路由并建立 P2P 连接（复用已有连接）。
- 切换点由一次 **OOB AllGather** 决定：取所有 GPU 的**最小调度版本号**（保证各卡均可用）与**最大序列号 K**（切换点）；≤K 的操作走旧调度，之后走新调度。
- 依赖 NCCL 在同一 communicator 内的顺序与串行化保证，新旧调度不会并发，无需排空在途操作；切换按 communicator 隔离。

**Measurement（被动遥测）**

- 仅针对**无 reduction 阶段**的 collective，避免归约算术干扰吞吐测量。
- **三级内存层次**：
  - *Cache*（GPU Shared Memory，每 TB）：聚合 count/sum_bw；
  - *Accumulator*（GPU Global Memory，每目的地）：记录 active channel 数、bytes_sent、start/start_size；
  - *Buffer*（Host pinned DRAM，每 TB 循环槽位）：带 flag 供 Host 读取，无槽位则丢弃。
- **条件测量算法**：仅当活跃 channel 数超过阈值 N（由 NCCL 拓扑发现或离线 profiling 确定）时开启测量窗口，低于阈值时关闭并计算 `BW = ΔSize/ΔTime`。
- **内核改造**：将 NCCL 单体 `postPeer` 拆为 `postPeerFence`（内存序）与 `postPeerNotify`（通知），复用 signaling warp 16 作为进度记录者，与 reduceCopy 循环并行，掩蔽同步与原子操作延迟。
- **intra-node**：P2P_DIRECT 直连，测每 GPU
